Data Warehousing.txt
1. What is a Data Warehouse?
Answer: A Data Warehouse is a centralised repository used to store historical data from multiple sources for reporting and analysis.

2. What are the main characteristics of a Data Warehouse?
Answer: Subject-oriented, Integrated, Time-variant and Non-volatile.

3. What is OLTP?
Answer: OLTP (Online Transaction Processing) handles day-to-day transactional operations such as INSERT, UPDATE and DELETE.

4. What is OLAP?
Answer: OLAP (Online Analytical Processing) supports complex queries and analytical reporting on large volumes of data.

5. What is the difference between OLTP and OLAP?
Answer: OLTP handles daily transactions, whereas OLAP is designed for analytical queries and decision-making.

6. What is ETL?
Answer: ETL stands for Extract, Transform and Load, which moves data from source systems into a target system.

7. What is ELT?
Answer: ELT stands for Extract, Load and Transform, where data is transformed after loading into the target platform.

8. What is the difference between ETL and ELT?
Answer: ETL transforms data before loading, whereas ELT loads data first and transforms it inside the target system.

9. What is a Data Mart?
Answer: A Data Mart is a smaller data repository designed for a specific business department, such as Sales or Finance.

10. What is a Staging Area?
Answer: A Staging Area is a temporary storage location where source data is collected before transformation and loading.

11. What is Metadata?
Answer: Metadata is data about data, describing its structure, meaning, source and format.

12. What is a Data Lake?
Answer: A Data Lake stores large amounts of raw structured, semi-structured and unstructured data.

13. What is the difference between a Data Lake and a Data Warehouse?
Answer: A Data Lake stores raw data in different formats, whereas a Data Warehouse stores structured and processed data for analytics.

14. What is a Fact Table?
Answer: A Fact Table stores measurable business data such as Sales, Quantity, Revenue and Profit.

15. What is a Dimension Table?
Answer: A Dimension Table stores descriptive business information such as Customer, Product, Date and Location.

16. What is a Star Schema?
Answer: A Star Schema is a dimensional model where a central fact table connects directly to multiple dimension tables.

17. What is a Snowflake Schema?
Answer: A Snowflake Schema is a dimensional model where dimension tables are further normalised into related tables.

18. What is the difference between Star Schema and Snowflake Schema?
Answer: Star Schema uses denormalised dimensions, whereas Snowflake Schema uses normalised dimensions.

19. What is a Galaxy Schema?
Answer: A Galaxy Schema, also called a Fact Constellation Schema, contains multiple fact tables sharing common dimensions.

20. What is a Grain in Data Modelling?
Answer: Grain defines the level of detail represented by each row in a fact table.

21. Why is defining grain important?
Answer: Grain ensures that every fact table row has a clearly defined business meaning and prevents incorrect aggregation.

22. What is a Surrogate Key?
Answer: A Surrogate Key is a system-generated unique identifier used as a primary key in a dimension table.

23. What is a Natural Key?
Answer: A Natural Key is a business-generated identifier, such as Customer ID or Employee ID.

24. What is the difference between Surrogate Key and Natural Key?
Answer: A Surrogate Key is system-generated, whereas a Natural Key comes from the source business system.

25. What is a Primary Key in Data Modelling?
Answer: A Primary Key uniquely identifies each record in a table.

26. What is a Foreign Key?
Answer: A Foreign Key connects one table to another by referencing a primary or unique key.

27. What is a Measure?
Answer: A Measure is a numerical value in a fact table that can be analysed, such as Sales, Profit or Quantity.

28. What is a Dimension Attribute?
Answer: A Dimension Attribute is a descriptive column used to filter, group or analyse data.

29. What is a Degenerate Dimension?
Answer: A Degenerate Dimension is a dimension attribute stored directly in the fact table without a separate dimension table, such as Order Number.

30. What is a Conformed Dimension?
Answer: A Conformed Dimension is a shared dimension used consistently across multiple fact tables or data marts.

31. What is a Role-Playing Dimension?
Answer: A Role-Playing Dimension is one dimension used multiple times for different purposes, such as Order Date and Delivery Date.

32. What is a Junk Dimension?
Answer: A Junk Dimension combines multiple low-cardinality flags and indicators into one dimension table.

33. What is a Slowly Changing Dimension (SCD)?
Answer: SCD manages historical changes in dimension attributes over time.

34. What is SCD Type 1?
Answer: SCD Type 1 overwrites old values with new values without maintaining historical records.

35. What is SCD Type 2?
Answer: SCD Type 2 creates a new dimension record to maintain complete historical changes.

36. What is SCD Type 3?
Answer: SCD Type 3 stores limited historical information using additional columns, such as Current City and Previous City.

37. What is a Factless Fact Table?
Answer: A Factless Fact Table stores business events or relationships without numerical measures.

38. What are the different types of Fact Tables?
Answer: Transaction Fact, Periodic Snapshot Fact and Accumulating Snapshot Fact.

39. What is a Transaction Fact Table?
Answer: A Transaction Fact Table stores individual business transactions, such as each sales order line.

40. What is a Periodic Snapshot Fact Table?
Answer: A Periodic Snapshot Fact Table stores measurements at regular intervals, such as daily or monthly account balances.

41. What is an Accumulating Snapshot Fact Table?
Answer: An Accumulating Snapshot Fact Table tracks a business process through multiple milestones, such as order processing and delivery.

42. What is Normalisation?
Answer: Normalisation organises data into multiple related tables to reduce redundancy and improve data integrity.

43. What is Denormalisation?
Answer: Denormalisation combines data to reduce joins and improve query performance for analytical workloads.

44. What is 1NF?
Answer: First Normal Form requires each column to contain atomic values without repeating groups.

45. What is 2NF?
Answer: Second Normal Form requires 1NF and no partial dependency on a part of a composite candidate key.

46. What is 3NF?
Answer: Third Normal Form requires 2NF and no transitive dependency of non-key attributes on candidate keys.

47. What is a Composite Key?
Answer: A Composite Key consists of two or more columns that together uniquely identify a record.

48. What is Data Granularity?
Answer: Data Granularity refers to the level of detail stored in a data warehouse.

49. What is Data Cleansing?
Answer: Data Cleansing identifies and corrects inaccurate, duplicate, missing or inconsistent data.

50. What is Data Profiling?
Answer: Data Profiling analyses source data to understand its quality, structure, completeness and consistency.

51. What is Incremental Loading?
Answer: Incremental Loading loads only new or modified records instead of reloading the entire dataset.

52. What is Full Loading?
Answer: Full Loading loads the complete dataset from the source into the target system.

53. What is CDC?
Answer: CDC (Change Data Capture) identifies and captures INSERT, UPDATE and DELETE changes from source systems.

54. What is a Data Pipeline?
Answer: A Data Pipeline is a sequence of processes that moves and transforms data from source systems to target systems.

55. What is Data Lineage?
Answer: Data Lineage tracks the origin, movement and transformation of data throughout its lifecycle.

56. What is a Dimension Hierarchy?
Answer: A Dimension Hierarchy organises dimension attributes into levels, such as Country → State → City.

57. What is a Date Dimension?
Answer: A Date Dimension contains calendar attributes such as Date, Month, Quarter, Year and Weekday.

58. What is a Bridge Table?
Answer: A Bridge Table handles complex relationships, particularly many-to-many relationships between dimensions and facts.

59. What is a Many-to-Many Relationship?
Answer: A Many-to-Many Relationship occurs when multiple records in one table relate to multiple records in another table.

60. What is a Data Warehouse Bus Matrix?
Answer: A Bus Matrix identifies business processes and the conformed dimensions shared across different fact tables.

Performance Optimization.txt
How to improve dashboard performance in Tableau, Qlik Sense and Power BI

“ I improve dashboard performance by optimising the data model, reducing unnecessary data, simplifying calculations, limiting visuals, using efficient filters and optimising data refresh and query execution.”

1. Common performance improvement techniques
1. Remove unnecessary columns and rows from the source.
2. Use aggregated data wherever detailed data is not required.
3. Avoid unnecessary calculated fields and complex expressions.
4. Use a proper Star Schema with fact and dimension tables.
5. Avoid many-to-many relationships unless required.
6. Reduce the number of visuals on a single dashboard page.
7. Avoid unnecessary filters and slicers.
8. Use efficient joins and avoid duplicate records.
9. Implement incremental refresh or incremental data loading.
10. Measure performance using the tool's built-in performance analysis features.


Tableau – Performance optimization
1. Use Extract instead of Live: Use Hyper extracts when real-time data is not required.
2. Reduce data volume: Apply extract filters and data source filters to load only required records.
3. Hide unused columns: Remove unnecessary fields before creating extracts.
4. Reduce marks: Avoid displaying thousands of unnecessary data points in charts.
5. Limit dashboard worksheets: Avoid putting too many charts on one dashboard.
6. Reduce quick filters: Too many filters can generate additional queries.
7. Use Apply button: Allow users to select multiple filter values and execute the query once.
8. Optimise calculations: Avoid deeply nested calculations and unnecessary table calculations.
9. Optimise LOD expressions: Avoid unnecessarily detailed FIXED, INCLUDE and EXCLUDE calculations.
10. Use database calculations: Push complex row-level calculations to SQL or the database when appropriate.
11. Avoid unnecessary COUNTD: Distinct count calculations can be expensive on large datasets.
12. Use dashboard actions: Use filter actions to guide users from summary to detailed views instead of displaying everything together.
13. Remove unused worksheets: Delete unused sheets, fields and data sources.
How to identify performance issues:
- Performance Recording: Help → Settings and Performance → Start Performance Recording.
- Workbook Optimizer: Check workbook design recommendations.
- Identify whether the problem is query execution, calculation, connection or rendering.
Official references: 
Tableau+2

Qlik Sense – Performance optimization
1. Use QVD files: Store transformed data in QVD files for faster loading.
2. Use optimized QVD loading: Avoid transformations during the load when you want optimized QVD loading.
3. Remove synthetic keys: Avoid multiple common fields between tables unless intentionally designed.
4. Remove circular references: Design a clean associative data model.
5. Use a star schema: Keep fact and dimension tables structured properly.
6. Reduce data volume: Load only required fields and records.
7. Pre-aggregate data: Aggregate data in the load script when users do not need transaction-level details.
8. Avoid unnecessary IF expressions: Especially inside aggregation functions.
9. Prefer Set Analysis: Use Set Analysis instead of row-by-row IF conditions where the logic allows it.
10. Simplify chart expressions: Avoid complex nested IF, Aggr and calculated dimensions where possible.
11. Reduce table columns: Avoid displaying too many dimensions and measures in straight tables.
12. Use mapping loads: Use ApplyMap() for simple lookup transformations instead of unnecessary joins.
13. Avoid unnecessary joins: Use associations between tables when appropriate.
14. Optimise reload scripts: Use incremental loading for large datasets when suitable.
15. Reduce objects per sheet: Too many charts and objects can affect sheet rendering.
Example: IF vs Set Analysis

Less efficient for a large dataset:
Sum(If(Region = 'East', Sales))


Often more efficient:
Sum({<Region={'East'}>} Sales)


How to identify performance issues:
- Use Qlik Sense App Performance Evaluation.
- Inspect the Data Model Viewer for synthetic keys and circular references.
- Check reload time, app size, chart response time and memory usage.
Official references: 
Qlik Help+2


Power BI – Performance optimization
1. Use Star Schema: Separate fact and dimension tables.
2. Reduce data volume: Remove unnecessary rows and columns in Power Query.
3. Use Import mode: Prefer Import mode when real-time data is not required and the dataset fits available capacity.
4. Use DirectQuery carefully: DirectQuery performance depends heavily on the underlying database and query design.
5. Enable Query Folding: Push Power Query transformations back to the source database wherever possible.
6. Use Incremental Refresh: Refresh only recent or changed data instead of the entire historical dataset.
7. Optimise DAX: Avoid unnecessarily complex calculations and nested iterators.
8. Use variables: Store intermediate results using VAR and reuse them.
9. Avoid unnecessary FILTER: Prefer Boolean filter arguments in CALCULATE when appropriate.
10. Avoid unnecessary calculated columns: Use measures when the calculation needs to respond dynamically to filters.
11. Optimise relationships: Prefer one-to-many relationships and avoid unnecessary bidirectional filtering.
12. Reduce visuals: Avoid too many visuals on one report page.
13. Limit slicers: Avoid high-cardinality slicers and unnecessary visual interactions.
14. Use aggregations: Create summary tables for large datasets when appropriate.
15. Avoid unnecessary high-cardinality columns: Columns containing unique transaction IDs can increase model size.
Example: DAX optimization

Less efficient:
East Sales =
CALCULATE(
    SUM(Sales[Sales]),
    FILTER(
        Sales,
        Sales[Region] = "East"
    )
)


Usually simpler and more efficient:
East Sales =
CALCULATE(
    SUM(Sales[Sales]),
    Sales[Region] = "East"
)


How to identify performance issues:
- Performance Analyzer: View → Performance Analyzer.
- DAX Studio: Analyse slow DAX queries and server timings.
- Power Query: Check whether query folding is working.
- Model view: Check relationships and model structure.

Powerbi.txt
What is Power BI?
Answer: Power BI is a Microsoft Business Intelligence tool used to connect, transform, model, visualise and analyse data.



What is DAX?
Answer: DAX (Data Analysis Expressions) is a formula language used in Power BI for calculations and data analysis.



What are the different types of calculations in Power BI?
Answer: Calculated Columns, Measures and Calculated Tables are the three major types of DAX calculations.



What is a Calculated Column?
Answer: A Calculated Column creates a new column in a table by evaluating a DAX expression for every row.



What is a Measure?
Answer: A Measure is a dynamic calculation evaluated based on the current filter context of a report.



What is the difference between a Calculated Column and a Measure?
Answer: A Calculated Column is calculated row by row and stored in the model, whereas a Measure is calculated dynamically when used in a visual.



What is Row Context?
Answer: Row Context means DAX evaluates an expression for the current row of a table.



What is Filter Context?
Answer: Filter Context is the set of filters applied to a calculation through slicers, visual filters, page filters, report filters or DAX expressions.



What is the difference between Row Context and Filter Context?
Answer: Row Context evaluates calculations for the current row, whereas Filter Context determines which rows are included in a calculation.



What is Context Transition?
Answer: Context Transition converts Row Context into Filter Context, commonly performed by the CALCULATE function.



What is CALCULATE in DAX?
Answer: CALCULATE evaluates an expression after modifying or adding filter conditions.



What is the difference between CALCULATE and CALCULATETABLE?
Answer: CALCULATE returns a scalar value, whereas CALCULATETABLE returns a table after applying filter conditions.



What is FILTER in DAX?
Answer: FILTER returns a table containing only the rows that satisfy a specified condition.



What is the difference between CALCULATE and FILTER?
Answer: CALCULATE modifies filter context, whereas FILTER returns a filtered table that can be used as a filter argument.



What is ALL in DAX?
Answer: ALL removes filters from a specified table or column and returns all applicable rows or values.



What is ALLEXCEPT in DAX?
Answer: ALLEXCEPT removes all filters from a table except the filters on specified columns.



What is the difference between ALL and ALLEXCEPT?
Answer: ALL removes filters from specified tables or columns, whereas ALLEXCEPT removes all filters from a table except specified columns.



What is ALLSELECTED?
Answer: ALLSELECTED removes filters applied inside the query or visual while retaining external filters such as slicer selections.



What is REMOVEFILTERS?
Answer: REMOVEFILTERS clears filters from specified tables or columns inside CALCULATE.



What is the difference between ALL and REMOVEFILTERS?
Answer: Both can remove filters, but ALL can also return a table, whereas REMOVEFILTERS is specifically used as a filter modifier.



What is KEEPFILTERS?
Answer: KEEPFILTERS adds a filter while intersecting it with existing filters instead of replacing filters on the same columns.



What is RELATED in DAX?
Answer: RELATED retrieves a value from a related table, typically through a many-to-one relationship, in row context.



What is RELATEDTABLE?
Answer: RELATEDTABLE returns the related rows from another table, typically using the current row context.



What is the difference between SUM and SUMX?
Answer: SUM adds values from a single column, whereas SUMX evaluates an expression row by row and then sums the results.



What is the difference between COUNT and COUNTA?
Answer: COUNT counts non-blank values in supported numeric or date columns, whereas COUNTA counts non-blank values of supported data types.



What is COUNTROWS?
Answer: COUNTROWS returns the number of rows in a table or filtered table expression.



What is DISTINCTCOUNT?
Answer: DISTINCTCOUNT counts the unique values in a specified column, including BLANK as a distinct value.



What is DIVIDE in DAX?
Answer: DIVIDE performs division safely and allows an alternative result when the denominator is zero or blank.



What is IF in DAX?
Answer: IF evaluates a logical condition and returns one value when TRUE and another when FALSE.



What is SWITCH in DAX?
Answer: SWITCH evaluates an expression against multiple conditions and returns the corresponding result.



What is VAR in DAX?
Answer: VAR stores the result of an expression in a variable for reuse within a DAX calculation.



What is RETURN in DAX?
Answer: RETURN specifies the final expression or result of a DAX formula after variable declarations.



What is the difference between IF and SWITCH?
Answer: IF is suitable for conditional branching, whereas SWITCH is useful for handling multiple possible conditions or values.



What is a calculated table?
Answer: A calculated table is a new table created using a DAX expression and stored in the data model.



What is a Virtual Table in DAX?
Answer: A Virtual Table is a temporary table created during DAX evaluation using functions such as FILTER, SUMMARIZE and ADDCOLUMNS.



What is SUMMARIZE?
Answer: SUMMARIZE creates a grouped table based on specified columns and can include calculated expressions.



What is ADDCOLUMNS?
Answer: ADDCOLUMNS adds calculated columns to an existing table expression.



What is SELECTEDVALUE?
Answer: SELECTEDVALUE returns the selected value when exactly one distinct value is available; otherwise, it returns an alternate result or BLANK.



What is HASONEVALUE?
Answer: HASONEVALUE checks whether exactly one distinct value is present in the filter context for a column.



What is ISFILTERED?
Answer: ISFILTERED checks whether a column or table is directly filtered.



What is USERELATIONSHIP?
Answer: USERELATIONSHIP activates an existing inactive relationship temporarily within a calculation.



What is CROSSFILTER?
Answer: CROSSFILTER changes the cross-filter direction or disables a relationship for a specific calculation.



What is the difference between a calculated column and a calculated table?
Answer: A Calculated Column adds a column to an existing table, whereas a Calculated Table creates a new table.



What is a Time Intelligence function in DAX?
Answer: Time Intelligence functions perform date-based calculations such as YTD, MTD, QTD and previous-year comparisons.



What is TOTALYTD?
Answer: TOTALYTD calculates the year-to-date total for a specified expression.



What is DATESYTD?
Answer: DATESYTD returns a table containing dates from the beginning of the year up to the current date in context.



What is SAMEPERIODLASTYEAR?
Answer: SAMEPERIODLASTYEAR returns the corresponding dates from the previous year.



What is DATEADD?
Answer: DATEADD shifts the dates in the current context forward or backward by a specified interval.



What is PREVIOUSMONTH?
Answer: PREVIOUSMONTH returns the dates belonging to the previous month based on the current date context.



What is DATESINPERIOD?
Answer: DATESINPERIOD returns a date range based on a specified starting date, interval and number of intervals.



What is RANKX?
Answer: RANKX evaluates an expression over a table and returns the ranking of a value.



What is TOPN?
Answer: TOPN returns the top N rows from a table based on a specified expression.



What is LOOKUPVALUE?
Answer: LOOKUPVALUE retrieves a value from a table based on matching search conditions.



What is COALESCE?
Answer: COALESCE returns the first expression that is not BLANK.



What is BLANK in DAX?
Answer: BLANK represents an empty or missing value in DAX calculations.



What is the difference between BLANK and 0?
Answer: BLANK represents a missing or empty value, whereas zero is a numeric value.



What is a Running Total?
Answer: A Running Total calculates the cumulative value of a measure across a selected sequence, such as dates.



What is Year-over-Year (YoY) Growth?
Answer: YoY Growth measures the percentage change in a metric compared with the same period in the previous year.



What is Month-over-Month (MoM) Growth?
Answer: MoM Growth measures the percentage change in a metric compared with the previous month.



What is a Dynamic Measure?
Answer: A Dynamic Measure changes its calculation or displayed result based on slicers, selections or other filter conditions.



What is the difference between a Measure and an Implicit Measure?
Answer: An Explicit Measure is created using a DAX formula, whereas an Implicit Measure is automatically generated when a numeric column is aggregated in a visual.



What is a Date Table?
Answer: A Date Table is a dedicated calendar table containing continuous dates and attributes such as Year, Quarter, Month and Day.



Why do we mark a Date Table in Power BI?
Answer: Marking a Date Table identifies the official date column for consistent time intelligence calculations.



What is bidirectional filtering?
Answer: Bidirectional filtering allows filters to propagate in both directions between related tables.



What is an inactive relationship?
Answer: An inactive relationship exists between tables but does not automatically propagate filters until activated using USERELATIONSHIP.



What is the difference between a measure and a calculated column in terms of storage?
Answer: Calculated Columns consume model storage, whereas Measures store their definitions and calculate results when queried.



What is an iterator function in DAX?
Answer: An iterator function evaluates an expression row by row over a table, such as SUMX, AVERAGEX and MAXX.



What is the difference between SUMX and AVERAGEX?
Answer: SUMX adds the evaluated row-level results, whereas AVERAGEX calculates their average.



What is the difference between ALLSELECTED and REMOVEFILTERS?
Answer: ALLSELECTED preserves relevant external selections, whereas REMOVEFILTERS clears specified filters.



What is the difference between a row context and a context transition in a calculated column?
Answer: A calculated column has row context, and using CALCULATE can convert that row context into filter context.

3. Save the .pbix file.
4. Sign in to Power BI Desktop using your organisational account.
5. Select Home → Publish.

SQL Interview Questions and Answers – 60 Important Questions
For Freshers | One-line Answers | Interview Preparation

1. What is SQL?
Answer: SQL (Structured Query Language) is used to store, retrieve, manipulate and manage data in relational databases.

2. What is a database?
Answer: A database is an organised collection of data stored electronically.

3. What is a table?
Answer: A table stores data in rows and columns.

4. What is a primary key?
Answer: A primary key uniquely identifies each record and does not allow NULL or duplicate values.

5. What is a foreign key?
Answer: A foreign key establishes a relationship between two tables by referencing a primary or unique key.

6. What is the difference between WHERE and HAVING?
Answer: WHERE filters rows before grouping, whereas HAVING filters groups after GROUP BY.

7. What is the difference between DELETE, TRUNCATE and DROP?
Answer: DELETE removes selected rows, TRUNCATE removes all rows, and DROP removes the entire table structure.

8. What is NULL in SQL?
Answer: NULL represents a missing or unknown value, not zero or an empty string.

9. What is a JOIN in SQL?
Answer: JOIN combines records from two or more tables based on a related column.

10. What is INNER JOIN?
Answer: INNER JOIN returns only matching records from both tables.

11. What is LEFT JOIN?
Answer: LEFT JOIN returns all records from the left table and matching records from the right table.

12. What is RIGHT JOIN?
Answer: RIGHT JOIN returns all records from the right table and matching records from the left table.

13. What is FULL OUTER JOIN?
Answer: FULL OUTER JOIN returns matching and non-matching records from both tables.

14. What is CROSS JOIN?
Answer: CROSS JOIN returns the Cartesian product of two tables.

15. What is SELF JOIN?
Answer: SELF JOIN joins a table with itself to compare related records within the same table.

16. What is the difference between INNER JOIN and LEFT JOIN?
Answer: INNER JOIN returns matching records only, whereas LEFT JOIN also returns unmatched left-table records.

17. What is an equi join?
Answer: An equi join uses the equality operator (=) to match records between tables.

18. What is a subquery?
Answer: A subquery is a query written inside another SQL query.

19. What is a correlated subquery?
Answer: A correlated subquery depends on values from the outer query and executes logically for each outer row.

20. What is a non-correlated subquery?
Answer: A non-correlated subquery executes independently of the outer query.

21. What is the difference between IN and EXISTS?
Answer: IN checks whether a value matches a list, whereas EXISTS checks whether the subquery returns any rows.

22. What is a scalar subquery?
Answer: A scalar subquery returns exactly one row and one column.

23. Can we use a subquery in the FROM clause?
Answer: Yes, a subquery in the FROM clause acts as a derived table.

24. How do you find employees earning more than the average salary?
Answer: Use a subquery with AVG(Salary) in the WHERE clause.

25. What are set operators in SQL?
Answer: Set operators combine the results of two or more SELECT statements.

26. What is UNION?
Answer: UNION combines results and removes duplicate records.

27. What is UNION ALL?
Answer: UNION ALL combines results without removing duplicate records.

28. What is the difference between UNION and UNION ALL?
Answer: UNION removes duplicates, whereas UNION ALL retains duplicates and is generally faster.

29. What is INTERSECT?
Answer: INTERSECT returns only the common records from both SELECT statements.

30. What is MINUS or EXCEPT?
Answer: MINUS or EXCEPT returns records from the first query that are not present in the second query.

31. What are the requirements for using set operators?
Answer: SELECT statements must have the same number of columns with compatible corresponding data types.

Answer: DDL (Data Definition Language) defines and modifies database structures.

34. What is CREATE?
Answer: CREATE is used to create database objects such as tables, views and databases.

35. What is ALTER?
Answer: ALTER modifies the structure of an existing database object.

36. What is DROP?
Answer: DROP permanently removes a database object and its structure.

37. What is DML?
Answer: DML (Data Manipulation Language) is used to insert, update and delete records in database tables.

38. What are DML commands?
Answer: INSERT, UPDATE and DELETE are common DML commands.

39. What is INSERT?
Answer: INSERT adds new records into a table.

40. What is UPDATE?
Answer: UPDATE modifies existing records in a table.

41. What is DELETE?
Answer: DELETE removes records from a table, optionally based on a WHERE condition.

Answer: DCL (Data Control Language) manages database access permissions and user privileges.

43. What are DCL commands?
Answer: GRANT and REVOKE are the primary DCL commands.

44. What is GRANT?
Answer: GRANT provides database permissions to users or roles.

45. What is REVOKE?
Answer: REVOKE removes previously granted database permissions.

46. What is TCL?
Answer: TCL (Transaction Control Language) manages database transactions.

47. What is COMMIT?
Answer: COMMIT permanently saves the changes made in the current transaction.

48. What is ROLLBACK?
Answer: ROLLBACK undoes uncommitted changes in the current transaction.

49. What is SAVEPOINT?
Answer: SAVEPOINT creates a point within a transaction to which we can partially roll back.

50. What are ACID properties?
Answer: ACID stands for Atomicity, Consistency, Isolation and Durability, ensuring reliable database transactions.

52. How do you find the second-highest salary?
Answer: Use DENSE_RANK() or a subquery with MAX().

53. How do you find the highest salary in each department?

54. What is a view?

55. What is an index?

56. What is the difference between CHAR and VARCHAR?
Answer: CHAR stores fixed-length strings, whereas VARCHAR stores variable-length strings.
